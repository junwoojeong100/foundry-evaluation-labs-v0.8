# 기여와 실습 재현성 유지

[English](maintaining.en.md) · [호환성](compatibility.ko.md) · [메인 가이드](../README.ko.md)

**실행 가능한 명령, 두 언어 문서, 예제와 실제 증거의 경계를 함께 유지합니다.** 점수가 좋아진다는 이유로 테스트를 완화하거나 이전 결과를 고치지 않습니다.

## 문제를 안전하게 보고

저장소의 **Issues → New issue → Workshop problem** 양식을 사용합니다. 문서·절, 언어, 명령, 기대한 완료 표시와 실제 표시, Python·패키지·CLI 버전, **민감정보를 제거한** 오류를 적습니다. 오프라인 입문과 실제 클라우드 단계 중 어디서 발생했는지도 구분합니다.

`.env`, 토큰, 계정·구독 식별자, 원본 trace, 실제 결과 폴더, 가리지 않은 화면은 첨부하지 않습니다. Issue는 공개됩니다. 자격 증명 노출이 의심되면 조직 절차로 회전·폐기하고, 노출을 입증하려고 값을 공개하지 않습니다.

## 변경은 필요한 범위에 집중

1. 코드와 직접 관련된 한국어·영어 안내를 함께 바꿉니다. 기존 링크가 유지되도록 고정 앵커를 보존합니다.
2. 원래 증상의 회귀 테스트를 추가합니다. 최소 합성 입력을 사용하고 고객 데이터나 실제 클라우드 결과를 넣지 않습니다.
3. 기존 helper와 명령 파서를 재사용합니다. 실제 업무 검사와 몰래 달라지는 별도의 “데모 평가기”를 만들지 않습니다.
4. 로컬에서 확인한 것과 승인된 Azure 리허설이 필요한 것을 구분합니다.

새 기여용 clone에서는 실습과 같은 Python 3.13 환경을 준비합니다.

```bash
python3.13 -m venv src/agent/.venv &&
source src/agent/.venv/bin/activate &&
python -m pip install -r requirements.lock.txt
```

**완료 확인:** 패키지 설치가 끝납니다. **다르면:** [오프라인 테스트 복구](troubleshooting.ko.md#offline-tests)의 패키지·다운로드 진단을 따르고, 오류를 숨기려고 버전 고정을 바꾸지 않습니다.

저장소 루트에서 오프라인 테스트를 실행합니다.

```bash
python -m unittest discover -s tests -v
```

**완료 확인:** `OK`입니다. Azure 인증은 필요 없습니다. 문서 검사는 로컬 링크·앵커, Bash 문법, 실제 CLI 파서 인수, 한영 명령 대응, 단계 간 연결을 확인합니다. **다르면:** 실패한 동작이나 잘못된 문서를 고치며 초록색으로 만들기 위해 assertion을 삭제하지 않습니다.

의존성 없는 경로도 별도로 확인합니다.

```bash
python -S -m unittest discover -s tests -p test_offline_lab.py -v
```

**완료 확인:** site packages를 끈 상태에서 `OK`입니다. 테스트는 `.env`·클라우드 데이터·에이전트 코드가 없는 최소 복사 폴더에서 두 언어를 실행하고 네트워크·외부 명령을 차단합니다. **다르면:** 잘못 추가된 런타임 의존성이나 입출력을 제거하지, 자격 증명 없는 검사를 건너뛰지 않습니다.

## 자동 CI가 하는 일

[`validate.yml`](../.github/workflows/validate.yml)은 게시 후 push·pull request·수동 실행에 반응합니다. 저장소 읽기 권한, 고정 action revision을 사용하며 Azure 로그인·secrets가 없습니다.

| 작업 | 설정된 검사 |
|---|---|
| 표준 라이브러리 입문 | Linux/Python 3.10, macOS/Python 3.13, Windows/Python 3.13. 두 언어 보고서와 오프라인 회귀 테스트 |
| 실습·문서 | Linux/Python 3.13. 기록된 의존성, `pip check`, 전체 오프라인 단위·문서 테스트 |

**유료 클라우드 릴리스 워크플로가 아닙니다.** [`ci/release-gate.yml`](../ci/release-gate.yml)은 소유자가 승인된 저장소에 게시하고 설정하기 전까지 비활성 템플릿으로 남습니다. 기본 PR 워크플로에 클라우드 로그인·자원 생성·유료 평가·원본 증거 업로드를 추가하지 않습니다. 특히 `pull_request_target`으로 외부 기여 코드를 높은 권한으로 실행하지 않습니다.

입문 예제의 의도한 회귀 때문에 기본 CI가 실패하지는 않습니다. 테스트는 선택 게이트가 **올바른 이유로 1을 반환하는지** 확인합니다.

## 저장소 이름 변경과 로컬 폴더 이동

두 언어 가이드의 GitHub 주소를 새 이름으로 갱신합니다. 이전 이름을 재사용하면 사라지는 리다이렉트에 의존하지 않습니다. clone 대상 폴더를 명시하고 뒤의 `cd`와 일치시킵니다. 로컬 폴더 이름, `azure.yaml`의 프로젝트 이름, Azure 자원 이름과 소유권 태그는 GitHub 주소가 아니므로 일괄 치환하지 않습니다.

GitHub에서 이름만 바꾸면 로컬 파일은 이동하지 않습니다. 로컬 실습 폴더까지 옮겼다면 가상환경은 그대로 이동해 재사용할 수 없습니다. 로컬 에이전트를 멈추고, 기존 환경을 보관한 상태에서 최종 경로에 해당 실습 폴더의 `requirements.lock.txt`로 다시 만듭니다. 활성화와 오프라인 검사를 확인한 뒤에만 백업을 정리합니다. 기존 `.workshop/<run>/config.json`은 `workspace`만 해당 실행의 새 절대 `workshop` 경로로 바꿉니다. `.env`, Azure 식별자, 소유권 기록, 소스 manifest, 이전 결과는 보존합니다.

**CI를 설정한 사본**의 이름이나 소유자를 바꿨다면 [CI 식별자 준비](level-3.ko.md#ci-setup)로 현재 subject 접두사를 다시 조회해 Azure federated credential의 전체 subject와 대조합니다. 다를 때만 식별자 소유자가 credential을 갱신합니다. 원본 실습 저장소의 이름만 바꾼 것은 별도 fork의 식별자를 바꾸지 않습니다.

## SDK·API·평가기·모델 업그레이드

업그레이드는 서식 수정이 아니라 **새 실험**으로 취급합니다.

| 변경 | 호환성을 주장하기 전에 필요한 최소 증거 |
|---|---|
| SDK·프레임워크·전송 계층 | 상위 호환성 변경 검토, 직접 의존성과 전체 스냅샷 함께 갱신, import·payload·조회·재개·오류·정리 검사 |
| 모델·judge | 배포 기능·리전·쿼터 확인, 식별·버전 고정, calibration, 기존 집단과 섞지 않는 새 baseline/candidate/holdout |
| 평가기·합격선 | 정의·버전·척도·필수 입력·좋고 나쁜 방향·기준값 기록, 영향받은 비교 전체 재실행 |
| 데이터·규정·지침 | 원본 해시와 결과 보존, 데이터 버전 생성, dev·holdout 누수 방지 |
| 포털·CLI | 실제 명령·완료 표시 확인, 도구 버전과 리허설 날짜를 출처 검토일과 별도로 기록 |

관계없는 전역 환경에서 전체 lock 스냅샷을 만들지 않습니다. 깨끗한 환경에서 의존성 그래프를 확인하고 `requirements.txt`·`src/agent/requirements.txt`·`requirements.lock.txt`의 일관성을 유지합니다.

새 공식 문서는 고정 실습보다 나중 SDK를 요구할 수 있습니다. [호환성 문서](compatibility.ko.md)에 2.3 → 2.4/2.5/2.7 차이를 기록했습니다. job ID를 직접 조회하는 코드에 `begin_...` 예제를 복사할 때 상태 보존과 재시도까지 함께 바꿔야 합니다.

오프라인 통과만으로 실제 호환성을 주장하지 않습니다. 예산·정리 범위를 먼저 합의한 승인된 격리 환경에서 영향받은 클라우드 경로를 리허설합니다. 실패 시도도 보존하고 남은 실패를 그대로 보고합니다. 문서·출처만 검토한 변경은 새 실제 실행 증거를 만들지 않습니다.

## 공개 주장은 추적 가능하게 유지

기록된 결과 표를 갱신하기 전에 실행 집단·언어·모델/judge/평가기 버전·원본 출처·입력 변경 여부를 보존합니다. 한국어 점수를 영문 표에 복사하지 않습니다. 합성 예제에는 합성 표시를 남기고 `.foundry` 증거와 섞지 않습니다.

외부 자료를 검토할 때는 정확한 공개 출처와 날짜를 연결하고 GitHub 비교는 revision을 고정합니다. 읽은 자료가 보여 주는 내용을 설명하지, 저장소 전체에 무엇이 없다고 추정하지 않습니다. 별점·최신 날짜·문서 수를 품질과 동일시하거나 근거 없는 전수 순위를 주장하지 않습니다.
